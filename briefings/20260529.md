### 一、Anthropic 上线 Claude Opus 4.8：fast mode 价格砍到 1/3，Messages API 支持 mid-task system 条目

1. 北京时间 2026-05-29 凌晨（华尔街见闻北京站文章时间 02:15:08，对应美西 5/28 上午），Anthropic 正式发布 Claude Opus 4.8，API 模型 ID 为 `claude-opus-4-8`，定价与 Opus 4.7 持平：常规模式 $5 / $25 per 1M tokens（输入/输出），fast mode $10 / $50 per 1M tokens、速度 2.5× 于常规模式；官方明确 fast mode "三倍便宜于前代 Opus 的 fast 路径"。新模型默认开启 "high effort"，并在效果选择器旁新增 effort 控件（`high` / `extra` 即 Claude Code 的 `xhigh` / `max`），上下文窗口 1M、最大输出 128K，全平台同步上线（claude.ai、Claude Code、Claude API、Amazon Bedrock、Vertex AI、Microsoft Foundry）。
2. 工程相关变化：① Anthropic 官方评测显示 Opus 4.8 "约比 Opus 4.7 少 4× 地放行代码缺陷"，并在 Online-Mind2Web 上拿到 84%（computer use / browser agent），Devin/Factory/Cognition 等早期合作方反馈"工具调用更克制、长任务更稳"；② Messages API 现在允许把 system 条目直接放进 `messages` 数组里，开发者可以在不打破 prompt cache、也不绕道 user turn 的情况下，在 Agent 运行过程中热更新权限、token 预算、环境上下文等 system 级指令——这是 Anthropic 第一次把"mid-task system update"做成一等公民；③ 模型在 Hebbia / Databricks Genie / CoCounsel 等代表性 agent 业务上分别给出 multimodal token 成本 -61%、long-running eval"信噪比明显提升"、Legal Agent Benchmark 首次破 10% all-pass 等数字（均来自合作方 quote）。
3. 配套发布的还有 "Dynamic Workflows"（详见条目二），以及全计划档位都可用的 effort 控件；Anthropic 同时预告将在未来几周向所有客户开放 Mythos 级（高于 Opus）模型，目前仅 Project Glasswing 网络安全场景下小范围试用。

为什么值得工程团队关注：这是 Anthropic 在不到 6 周内对 Opus 系列的第二次迭代（4 月中旬 Opus 4.7 → 5/29 Opus 4.8），加价为 0、fast mode 价格腰斩再腰斩，把"长程 agentic + 高 effort + computer use"档位的真实推理成本压到了一个新的位置；Messages API 的 mid-task system 条目则是过去一年里所有自建 agent harness 团队反复绕路的痛点，原生支持后直接影响 harness 设计与 cache 命中率。

最可能影响的环节：选型 / Agent harness / 成本治理 / 评测。

【工程意义】

## 工程工具链

### 二、Claude Code 推出 Dynamic Workflows research preview：单次最多 1,000 个子代理、并发上限 16，工作流脚本可重跑

1. 与 Opus 4.8 同步发布（Anthropic Claude 官博文章日期 May 28，对应北京时间 5/29 凌晨），Claude Code 推出 Dynamic Workflows research preview：Claude 自己写一段 JavaScript 编排脚本，由独立 runtime 在后台执行，会话仍保持可交互；runtime 硬限制并发子代理 ≤ 16、单次 run 累计 ≤ 1,000 个子代理；脚本本身不能直接读写文件系统或 shell，所有 IO 由子代理完成，中间结果存在脚本变量里而不是回灌到主对话。
2. 触发方式有两条：① 直接在 prompt 里包含 `workflow` 一词；② 启用 Claude Code 新增 `ultracode` 设置（=`xhigh` effort + 自动 workflow 编排，由 Claude 自行判断哪些任务值得开 workflow）；Claude Code 还内置 `/deep-research` 作为一条预置工作流。Max / Team / API 计划默认开启，Enterprise 计划默认关闭、需管理员在 Claude Code 设置中开启；Pro 用户可在 `/config` 的 Dynamic workflows 行单独打开。覆盖 Claude Code CLI、Desktop、VS Code 扩展，并跨 Claude API、Amazon Bedrock、Vertex AI、Microsoft Foundry。要求 Claude Code v2.1.154 及以上。
3. Anthropic 给出的早期落地案例之一是 Jarred Sumner 用 Dynamic Workflows 把 Bun 从 Zig 移植到 Rust：一条工作流负责把每个 Zig struct 字段映射到对应 Rust lifetime，第二条工作流为每个 `.zig` 写出行为等价的 `.rs`，"上百个 agent 并行 + 每个文件 2 个 reviewer"，再由 fix loop 推动 build / test 一路跑绿；最终约 75 万行 Rust、原 test suite 99.8% 通过、从首次提交到 merge 共 11 天。Anthropic 同时强调一次 workflow 的 token 消耗"显著高于普通 Claude Code 会话"，首次触发会显示将要执行的内容并要求确认。

为什么值得工程团队关注：这是当前最贴近"在 IDE/CLI 内一次性发起百级并行子代理 + 自动对抗式互查 + 可重跑的 orchestration 脚本"的官方 agent harness 实现，把 codebase-wide bug sweep、500 文件迁移、跨多源 cross-check research 等"过去需要工程师手搭多 agent 调度框架"的场景，下沉到了 Claude Code 的内置能力，对正在评估 multi-agent 工程化路径的团队是一份直接可对照的标准实现。

最可能影响的环节：流程 / 选型 / Agent 治理 / 成本治理。

【工程意义】
- 对开发：把"一条 prompt 一个 diff"的协作模式升级到"一条 prompt 一段 orchestration 脚本 + 多个子代理"，对大规模迁移、跨服务漏洞扫描、安全审计、性能 profile 等过去要单独搭 multi-agent 框架的工作，给出了一条不用自己写 scheduler 的官方路径；脚本结果存在变量里、不污染主对话上下文，可直接作为可复用的内部工具。
- 对测试：workflow 内置的"独立子代理 + adversarial reviewer + 反复收敛"模式是一个值得参考的"自带二次校验"的 agent 评测原型；可在内部建立"workflow 执行轨迹 → 失败模式分类 → 回归用例沉淀"的链路。
- 对流程：Max / Team / API 默认开启意味着团队 token 账单可能在 5/29 之后突然抬升；Enterprise 计划虽默认关闭，但仍需把"是否、对谁、在哪些仓库允许 Dynamic Workflows"纳入 admin 政策；同时建议要求开发者在打开 ultracode 前先用 `/config` 的 disable workflows 选项做一次成本兜底。

【建议动作】
- 立即可做：升级 Claude Code 到 ≥ v2.1.154，在一个非关键内部仓库（建议规模 < 1 万文件）跑一次 `Create a workflow: 在全仓库扫描所有 unsafe SQL 拼接` 这种受限 codebase bug sweep，记录 token 消耗、并发子代理峰值、最终 finding 的真阳率。
- 本周可验证：选一条历史上需要 1–2 天手工跑的小型迁移（如某个 API 弃用替换、配置项重命名），用 Dynamic Workflows 跑一遍，与既有 Codex / Cursor / 自建 multi-agent 路径对比单次完成率、PR 通过率、人工返工成本。
- 暂时观察：Enterprise 计划是否开启、ultracode 是否设为团队默认；Dynamic Workflows 在长时间（数小时到数天）run 下的断点续跑稳定性、对 Anthropic 后台资源/限流的实际占用。
