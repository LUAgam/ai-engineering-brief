## 生成式AI

### 一、面壁智能开源 MiniCPM5-1B + ForgeTrain：1B 端侧模型 + 首个 AI 自写的生产级训练框架

1. 北京时间 2026-05-26，面壁智能联合清华大学、OpenBMB 开源社区，正式发布并开源新一代端侧文本基座大模型 MiniCPM5-1B。官方表述：1B 参数规模在国际 AA-Index（Artificial Analysis Intelligence Index）榜单上超过了所有 2B 参数以下模型；相比 3 个月前的 Qwen3.5-2B，效果更好且参数量减半；INT4 量化后权重约 0.5GB，可在手机端和浏览器中运行。模型权重、训练数据集与部署方案全部开源，分发渠道包括 Hugging Face（`openbmb/MiniCPM5-1B`）、GitHub（`OpenBMB/MiniCPM`）、ModelScope（`OpenBMB/MiniCPM5-1B`）、GitCode、魔乐社区。
2. MiniCPM5-1B 的 Base Model 由面壁自研的训练框架 ForgeTrain 预训练完成。ForgeTrain 被官方描述为"全球首个完全由 AI 编写的生产级大模型预训练框架"，采用 Harness + Agent loop 技术，从分布式训练、并行策略、显存管理、通信效率、算子调用、硬件适配到训练稳定性，整条链路代码由 Agent 编写，无人类手工参与。框架将开源至 `github.com/OpenBMB/ForgeTrain`。
3. 性能数据（来自面壁/量子位报道）：在 NVIDIA H100 上，ForgeTrain 与 Megatron 训练结果对齐，速度领先约 10%（同等算力成本下降约 10%）；在华为昇腾上预训练 MiniCPM5-1B 相比昇腾原生框架也录得约 10% 加速，作为面壁后续国产算力训练链路的工程底座。

为什么值得工程团队关注：这是过去一年里第一次出现"训练框架本身由 Agent 写"并直接被用来训出公开开源模型的产品级案例；同时 1B 端侧模型 + INT4 0.5GB 权重把"AA-Index 头部能力"压到了浏览器/手机这一档，对在做端侧 AI、隐私敏感场景或离线 AI 助理的团队，是一份可以直接拉下来跑的现成基座。

最可能影响的环节：端侧部署 / 选型 / 训练框架与算力适配。

【工程意义】
- 对开发：可直接在手机/浏览器/边缘设备里嵌入 1B 文本能力，配合 INT4 路径做轻量助手、离线翻译、本地知识问答；模型权重 + 训练数据 + 部署方案三件都开源，方便复现与微调。
- 对测试：可在内部 AA-Index 子集、自家 1B/2B 端侧基准上加跑 MiniCPM5-1B，对照 Qwen3.5-2B、Phi 系列等同档模型；同时关注 ForgeTrain 与 Megatron 在自家集群上的复测速度差，验证 10% 加速是否在自家拓扑下成立。
- 对流程：在已经使用 Megatron / DeepSpeed / SGLang 的内部训练平台中，可以把 ForgeTrain 作为"全 Agent 化训练框架"参照样本，评估是否在自家训练 Pipeline 中切出一个由 Agent 维护的子模块（如 op 适配、分布式 schedule）。

【建议动作】
- 立即可做：拉取 `openbmb/MiniCPM5-1B`，在自家 INT4 推理栈（llama.cpp、MLC、ONNX Runtime 等）上跑通端侧 baseline；同时下载 base model 与后训练模型对比在自家任务上的提升。
- 本周可验证：等 `github.com/OpenBMB/ForgeTrain` 完整开放后，在内部 H100 / 昇腾集群跑一组小规模预训练任务，复测与 Megatron / 昇腾原生框架的速度、显存、收敛曲线差异。
- 暂时观察：ForgeTrain "由 Agent 全程编写"的可维护性、长期 bug 修复模式以及社区贡献流程；在没有第三方稳定性复测前，先不要替换公司主力训练框架。

### 二、昆仑万维天工 AI 发布 SkyClaw-v1.0 / lite：百万上下文 Agent 基座，原生跑 OpenClaw + Claude Code + Codex

1. 北京时间 2026-05-26，昆仑万维旗下天工 AI 正式发布高性能 Agent 模型 SkyClaw-v1.0，同步推出轻量版 SkyClaw-v1.0-lite，主页 `skyworkai.github.io/skyclaw/`。官方定位：百万 token 上下文，为"复杂工具调用、多轮任务执行、代码生成、文件编辑、交互式应用构建、研究型数据分析"等真实 Agent 工作流而设计；训练管线包含大规模 mid-train、高质量合成任务 SFT 与端到端 Agentic RL。模型已于 5/22 接入天工 Skywork 平台，登录 `tiangong.cn` 即可直接使用。
2. 兼容性与评测（官方表述）：原生适配 OpenClaw、Hermes、Nanobot 等主流 Agent 环境，并兼容 Claude Code、Codex 等代码 Agent 框架；官方页面称 SkyClaw-v1.0 在主流 Agent benchmark 上超过 Minimax 2.7、DeepSeek V4 Flash 与 Qwen 3.6 系列，OpenClaw 相关任务上接近 DeepSeek V4 Pro、Claude Opus 4.6、Qwen 3.6 Plus；lite 版定位高频/成本敏感场景，Agent 能力优于 Minimax 2.7。
3. 定价与开放方式：通过 `apifree.ai/model/skywork-ai/skyclaw-v1` 提供 OpenAI 兼容 API，支持流式输出、工具调用、多轮对话；公开定价 SkyClaw-v1.0 为输入 0.5 元/百万 tokens、输出 4 元/百万 tokens，lite 为 0.3 / 2 元，约为 Minimax 2.7 与 Qwen 3.6 系列的一半甚至更低；即日起两款模型 2–4 周限时免费开放试用，官方同时表示后续会"按版本逐步开源"。

## 工程工具链

### 三、GitHub Agentic Workflows `gh-aw` v0.76.1：`replay` 时间线日志、Inline Skill、Codex 默认升 `gpt-5.4`

1. 北京时间 2026-05-26 15:17（UTC 07:17），GitHub 在 `github/gh-aw`（GitHub Agentic Workflows，5K+ stars，Go 实现）发布 v0.76.1 预发布版本，标题概括为"timeline log visualization、inline skill、safe-outputs reliability、Codex model updates"。`gh-aw` 是 GitHub Next 与 Microsoft Research 共同开发的 GitHub Actions Agentic Workflow 工具，主打"在 GitHub Actions 里跑 Copilot / Claude / Codex / 自定义 engine 的可观测 + 安全 Agent"。
2. 该版本关键变化：① 新增 `replay` 命令，直接在终端中渲染并流式输出 unified timeline log，用于事后分析 Agent 单次跑流程（PR #34835）；② Inline skill 抽取/运行时，把 skill 定义和 inline sub-agent 语法对齐，可以直接在工作流里内联定义和执行 skill（#34874）；③ Codex 默认模型升级为 `gpt-5.4`，所有走 Codex engine 的工作流默认更新，lock 文件随之重新生成（#34804）；④ `tracker-id` frontmatter 正式纳入官方 reference 文档（#34799）；⑤ 安全增强：`safe-outputs push_to_pull_request_branch` 在合并历史分支上自动 linearize merge commit 后再 signed push，避免推送失败；并由 `github-actions[bot]` 跑了一次 "daily threat spec optimizer 2026-05-26 v1.0.12"。
3. 定位与使用方式：通过 `gh extension install github/gh-aw` 安装，工作流文件以 Markdown + YAML frontmatter 编写、再编译为 `.lock.yml` 给 GitHub Actions 执行；可被 issues / pull_request / workflow_run / schedule 等 10+ 事件触发，内置 5 层安全（read-only token、zero secrets、network firewall、safe outputs、threat detection）与 8+ safe output 类型（create-issue、create-pull-request、add-comment、add-label 等）。

为什么值得工程团队关注：这是当前最贴近"把 Agent 直接长在 GitHub Actions 上、并自带安全门禁与可观测"的官方实现，v0.76.1 把"事后 replay + inline skill + Codex 模型升档"三件一起补齐——对在做 PR 自动 triage、CI 自愈、安全审查 Agent 的团队，给出一个比自家硬搭 harness 更稳的官方路径。

最可能影响的环节：流程 / 可观测 / Agent 安全门禁。

【工程意义】
- 对开发：用 Markdown + YAML 描述工作流，再让 Copilot / Claude / Codex 引擎跑事件触发 Agent，避免在 CI 里手搓 shell 调 LLM；inline skill 让工作流里就能定义"小工具"，不必再单独发包。
- 对测试：`replay` 把 timeline log 拉回终端后，可以做 Agent 单次跑 step-by-step 复盘与回归用例沉淀；threat spec optimizer + safe-outputs 的合并校正，是值得参考的"Agent 写 PR 时的最小可信链路"参考实现。
- 对流程：Codex 默认升 `gpt-5.4` + lockfile 重生意味着升级会改动既有工作流可重复性，团队需在升级窗口里对比新旧模型在自家工作流上的行为差异；同时项目本身"early development、可能 break"的明确标注，要求生产场景仍按受控试点推进。

【建议动作】
- 立即可做：在一个非关键内部仓库装 `gh extension install github/gh-aw`，按官方 starter workflow 跑一条"CI 失败自动开修复 PR"或"issue triage"的 Agentic Workflow，记录 token、运行时长、PR 通过率。
- 本周可验证：在已有 Agent CI/CD 试点中，把 `replay` 命令接入团队周会复盘流程；把过去一周一次失败的 PR Agent 跑用 `gh aw replay` 重放一遍，沉淀至少 1 条新的 threat / failure pattern。
- 暂时观察：Codex 默认升 `gpt-5.4` 在自家工作流上的行为变化（特别是工具调用 schema 与 patch 行为）；如发现回归，使用 lock 文件锁定老版本模型，等观察 1–2 周后再统一切换。
