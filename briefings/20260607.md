2. 同窗口下，Claude Code 的 npm 镜像包 `@anthropic-ai/claude-agent-sdk` 已经从 5/29 的 v0.3.155 区间在 9 天内累计推到 v0.3.168（约 13 个 patch 版本），平均节奏 1.4 个 patch/天；Python 侧 `claude-agent-sdk` 在 BJT Jun 4 也走到 0.2.89。Anthropic 在 6/2 Code with Claude 大会 / 6/3 Claude Cyber Threat Report 之后没有放慢节奏，而是把工程动作压到 SDK / Claude Code / Managed Agents 三条线的小版本流上。
3. 配套官方 docs 仍维持 Managed Agents 必须传 `managed-agents-2026-04-01` beta header、`agent_toolset_20260401` 暴露 bash / file / web search / code execution 全套内置工具，beta 内 MCP tunnels 与 Dreaming 仍是 "more limited research preview" 状态——也就是说，这一波 SDK types 更新尚未对应任何模型层 / 工具层的破坏式变化。

为什么值得工程团队关注：① **Claude Code 这种"每天 chained 一 patch"型节奏，对在生产 / CI 中 pin 死 minor 版本的团队是一个明确风险**——你以为 `2.1.163`→`2.1.168` 都是 "Bug fixes and reliability improvements"，但社区 diff 显示底层 beta flag、feature flag、API endpoint、telemetry events 都在缓慢演进，跨越多个 patch 版本时实际行为可能已有差异。② **Managed Agents 仍在 beta 阶段持续微调 types**，对正在评估 / 试点把 cloud agent 任务跑在 Anthropic 托管 harness 上的团队，意味着 SDK 升级要做"types 兼容回归"而不是 "纯 patch upgrade"；③ 这一波版本 `claude-agent-sdk-typescript v0.3.166` 修的 `mcp_set_servers` runtime MCP server 资源工具注入问题，正是 6/2 Build 2026 一波 MCP-as-default 之后真实使用中出现的 corner case——团队若在 MCP server 数量较多 / 动态变化的场景下用 claude-agent-sdk，应优先升到 0.3.166+。

最可能影响的环节：开发 / 工具链版本治理 / CI 升级流程。

【工程意义】

### 二、Moonshot Kimi Code CLI 周末迭代 + BJT Jun 6 末段进入海外开发者视野：国产 TypeScript 终端 agent 进入 Claude Code / Codex / OpenCode 同形态梯队

1. **官方进度**：Moonshot AI（月之暗面）在 `MoonshotAI/kimi-code` 仓库（已 1.9k stars / 198 forks，2026-05-22 创建，MIT 协议）上 chained 推进 Kimi Code CLI 的 0.x 版本：changelog 显示 6 月内已经发布 0.7.0（BJT Jun 2）→ 0.8.0（BJT Jun 2）→ 0.9.0（BJT Jun 3）→ 0.10.0（BJT Jun 4）→ 0.10.1（BJT Jun 5）→ **0.11.0（BJT Jun 5 18:26）**，仓库最近一次 push 为 BJT Jun 6 23:17（30+ contributors，已合并若干文档与 CI 修复）。新版定位明确："The Starting Point for Next-Gen Agents"，作为旧 `kimi-cli`（Python 版）的继任，由 TypeScript 重写、npm `@moonshot-ai/kimi-code` 分发，附带二进制安装脚本（`curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash`，无需预装 Node.js）。
2. **能力面**：内置 `coder`、`explore`、`plan` 三类子 agent（隔离上下文，foreground/background 双模式，固定 30 分钟超时）；MCP 通过 `/mcp-config` 对话式添加，无需手写 JSON；支持 video 输入（屏幕录像 / 演示视频可直接拖入对话）；支持 Agent Client Protocol（ACP），可作为 ACP server 与第三方 ACP-compatible 编辑器 / IDE（如 Devin Desktop）协作；提供 lifecycle hooks（关键节点跑本地命令做高风险工具拦截、审计、桌面通知或对接自动化脚本）。可选 Zsh 集成与 VS Code 扩展（Marketplace `moonshot-ai.kimi-code`）。模型默认接 Moonshot Kimi 系列，配置后也可指向其他兼容供应商。CLI 本体 MIT 免费，模型调用通过 Kimi Code OAuth device flow 或 Moonshot AI Open Platform API key。
3. **海外覆盖时点**：BJT Jun 6 末段开始，海外开发者媒体（如 MarkTechPost 2026-06-06 ET）出现以 "Moonshot AI Releases Kimi Code CLI" 为题的覆盖，把 Kimi Code 与 Claude Code / Codex CLI / OpenCode 放在同一个对比表里（MIT 开源、TypeScript 实现、ACP、MCP、subagents、Bash / file / web 工具集等维度），事实上把它纳入"开源 TypeScript 终端 coding agent 第四选项"。同期国内一些 Kimi 相关报道把它与 5/20 之后 Anthropic Claude Code 的"agent OS shift" 趋势并提，但 Moonshot 官方未发独立 launch 博客（产品自 5 月底起以 GitHub Releases + 官方 docs 形式持续小步迭代）。

为什么值得工程团队关注：① **开源 TypeScript 终端 coding agent 阵营在 BJT 6/5-7 区间扩展到第四个 MIT 选项**（Claude Code 闭源 binary、OpenCode MIT TS、Codex CLI Apache-2.0 Rust、Kimi Code MIT TS），对内部需要"可审计 / 可自部署 / 可换模型 provider" 的团队是真实可选项——尤其是 Kimi Code 与 OpenCode 都是 TS 实现，团队可以从同一个 Node 工具链里 fork / patch / 加 hooks；② **Kimi Code 一上来就把 ACP（Agent Client Protocol）与 MCP 同时作为一等公民**——意味着它可以同时作为 Devin Desktop（详见 20260602 速递）等 ACP 编辑器里的 agent server，又作为本地 MCP host 拉外部工具，这与 Anthropic 6/2 在 Claude Code 上推 MCP-as-default 的方向是同一个工程语言；③ 国产侧 Kimi 模型在 SWE-Bench Verified 上的强势（K2.6 80.2%、压过 GPT-5.4，参见 ofox.ai 2026 横评）首次有了与"国际同形态 CLI agent" 配套的工程化外壳，对中文工程团队的"国产开源模型 + 国产 CLI 全链路自托管"是首次成立。

最可能影响的环节：开发 / 工具链选型 / 国产替代评估 / MCP-ACP 互操作。
